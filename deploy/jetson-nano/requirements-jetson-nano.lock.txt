# Every package the validated aarch64 image resolved, at the version it
# resolved to. Extracted from pose-est:nano after that image ran the pipeline
# end to end under emulation, so this file reproduces a stack that worked
# rather than re-deriving one.
#
# Build the air-gapped wheelhouse INSIDE that image -- native resolution, no
# --platform, no --python-version:
#
#   docker run --rm --platform linux/arm64 -v "$PWD/wheelhouse-nano:/wh" \
#       --entrypoint pip pose-est:nano \
#       download -r deploy/jetson-nano/requirements-jetson-nano.lock.txt pip -d /wh
#
# Note the trailing `pip`. On Ubuntu 18.04 aarch64, `python3.8 -m venv` seeds
# the environment with pip 9.0.1, which predates PEP 600 and refuses two
# wheels in this set outright -- polars' manylinux_2_24 tag and torchvision's
# bare linux_aarch64 one. An air-gapped board must therefore install pip from
# the wheelhouse before anything else:
#
#   .venv/bin/pip install --no-index --find-links wheelhouse-nano pip
#   .venv/bin/pip install --no-index --find-links wheelhouse-nano -r <this file>
#
# Do NOT reach for `pip download --platform manylinux2014_aarch64` on an x86
# host. --platform is a wheel-tag filter, not a description of the target: it
# leaves environment markers evaluating against the build host (torch's
# nvidia-* pins fire on x86 and are gone from PyPI, so the download fails),
# and any wheel whose tag is not in the list is silently walked back to an
# older version rather than reported -- which is how polars falls to 0.19.x
# and reads as though ultralytics were incompatible with Python 3.8. Two
# wheels here cannot be expressed by any manylinux list at all: polars is
# manylinux_2_24_aarch64, torchvision is the bare linux_aarch64 tag.
#
# requirements-jetson-nano.txt stays as the human-readable statement of
# intent; this file is what the board installs.
